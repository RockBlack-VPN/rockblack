# Publishing releases

All releases are built and published by GitHub Actions from `main`.
Platform versions follow the upstream version each one is built from
(`desktop/v2rayN/Directory.Build.props` → `<Version>`,
`android/V2rayNG/app/build.gradle.kts` → `versionName`).

## Android

1. Bump `versionName` **and** `versionCode` in `android/V2rayNG/app/build.gradle.kts`
   (or merge a newer upstream).
2. Run **Actions → Build Android → Run workflow** with **release** checked.

The workflow builds the signed APKs, creates `android-vX.Y.Z` titled
`Android vX.Y.Z` with `RockBlack.apk` (universal), `RockBlack-<abi>.apk` and
`SHA256SUMS`, then runs **Update platform download links**. An existing release
is never overwritten. A release is refused when the signing secrets are missing.

Signing secrets (Settings → Secrets and variables → Actions):

| Secret | Value |
|:--|:--|
| `ANDROID_KEYSTORE_BASE64` | base64 of the production keystore |
| `ANDROID_KEYSTORE_PASSWORD` | keystore password |
| `ANDROID_KEY_ALIAS` | key alias |
| `ANDROID_KEY_PASSWORD` | key password |

Always sign with the same production key, otherwise installed apps cannot be
upgraded. Keep an offline backup of the keystore.

## Desktop

1. Bump `<Version>` in `desktop/v2rayN/Directory.Build.props` (or merge a newer upstream).
2. Run **Actions → Build Desktop → Run workflow** with **release** checked.

The workflow builds Windows (x64 setup + x64/ARM64 portable), macOS (Apple
Silicon / Intel DMG) and Linux (x64/ARM64 DEB, RPM, portable ZIP), creates
`desktop-vX.Y.Z` titled `Desktop vX.Y.Z` with all assets and `SHA256SUMS`, then
runs **Update platform download links**.

## iOS

1. Bump `MARKETING_VERSION` in `ios/project.yml`.
2. Run **Actions → iOS build → Run workflow** on `main` with **release** checked.

The workflow builds the IPA and creates `ios-vX.Y.Z` titled `iOS vX.Y.Z`
with `RockBlack.ipa` (signed, when the `IOS_*` secrets are set) or
`RockBlack-unsigned.ipa`, plus `SHA256SUMS`, then runs **Update platform
download links** (`ios` entry in `RELEASE.json`). Signing secrets and install
notes: [ios/README.md](ios/README.md).

## Update feed and `latest`

`RELEASE.json` is the update feed. Every download URL is pinned to its
platform's versioned release. Manifest updates preserve the other platform,
refuse incomplete releases and never roll a platform back to an older version.

The permanent tag `latest` contains the current Desktop asset set and
`RockBlack.apk` for the current Android version; README buttons use
`/releases/download/latest/<asset>`. It is regenerated by
`scripts/sync_latest.py` — never upload to it by hand.

If an asset was uploaded late or a manifest commit failed, run
**Actions → Update platform download links** with the tag (for example
`android-v2.3.15`). Do not re-publish the binary to fix metadata.

Manual releases: create the tag/title/assets with the names above; publishing
the release triggers the manifest workflow automatically.

## Updating from upstream

```sh
# desktop
git clone --depth 1 https://github.com/2dust/v2rayN /tmp/v2rayN
# compare and port changes into desktop/, keep RockBlack branding (see branding/README.md)
# android
git clone --depth 1 https://github.com/2dust/v2rayNG /tmp/v2rayNG
```

Record the new upstream commit in [NOTICE.md](NOTICE.md).

Validation: `python3 -m unittest discover -s tests -v`.
