# RockBlack for iOS

SwiftUI client for iPhone and iPad (iOS 16+) built on
[Xray-core](https://github.com/XTLS/Xray-core) through
[libXray](https://github.com/XTLS/libXray). The UI follows
[branding/DESIGN.md](../branding/DESIGN.md) (RockBlack UI 3.0).

| | |
|:--|:--|
| App | `tech.rockblack.app` (`RockBlack`) |
| Packet tunnel extension | `tech.rockblack.app.tunnel` (`RockBlackTunnel.appex`) |
| App group | `group.tech.rockblack.app` |
| Languages | English, Russian, German |
| Version | `MARKETING_VERSION` in [project.yml](project.yml) → release tag `ios-vX.Y.Z` |

## Architecture

```
RockBlack.app (SwiftUI)                       RockBlackTunnel.appex (NEPacketTunnelProvider)
 ├─ subscriptions / links → libXray            ├─ utun fd from NetworkExtension
 │  convertShareLinksToXrayJson                ├─ Xray JSON + env {xray.tun.fd, xray.location.asset}
 ├─ ping: libXray pingBatch / TCP              ├─ libXray runXray → Xray native TUN inbound
 ├─ builds Xray JSON (routing profile)  ──────►├─ geosite.dat / geoip.dat (ru, private, category-ru, ads)
 └─ NETunnelProviderManager, provider messages └─ metrics → traffic counters for the app
```

* **Core:** the official `libxray-apple-cgo.zip` of libXray (pinned tag and
  SHA-256 in [scripts/fetch-libxray.sh](scripts/fetch-libxray.sh)), a static
  `LibXray.xcframework` with the C entry point `CGoInvoke` (API v3). Set
  `LIBXRAY_FROM_SOURCE=1` to build the same tag from source instead.
* **TUN:** Xray-core's own TUN inbound reads the NetworkExtension utun file
  descriptor (documented for iOS in Xray-core `proxy/tun/README.md`). No
  tun2socks layer, so the extension contains exactly one Go runtime and no
  SOCKS hop — the most memory-friendly option for the ~50 MB extension limit.
* **Geo data:** only the categories the routing profiles use are bundled
  (`geosite`: `category-ru`, `category-ads-all`; `geoip`: `ru`, `private`),
  cut from v2fly releases by [scripts/geo_subset.py](scripts/geo_subset.py)
  (~0.4 MB instead of ~26 MB).
* **DNS:** the tunnel advertises `1.1.1.1`; port 53 inside the tunnel is
  answered by Xray's DNS (Russia profile: Russian domains via `77.88.8.8`
  direct, others via `1.1.1.1` through the proxy). The proxy server's own
  host name is resolved before the tunnel comes up and pinned in `dns.hosts`.
* **Routing profiles:** Global, Russia (default), Block ads only, Direct.
  Changing the server or the profile while connected reloads Xray inside the
  running tunnel (provider message), falling back to a reconnect.
* **Imported routing profiles (Happ format):** `happ://routing/add/{base64}`
  (store) and `happ://routing/onadd/{base64}` (store + activate) from a
  subscription `routing` header, a `routing: happ://…` body line, a deep link
  (`happ://` / `rockblack://routing/…`) or pasted text. Mapping as on Android:
  BlockSites/BlockIp → block, private ranges direct, ProxySites/ProxyIp → proxy,
  DirectSites/DirectIp → direct, final rule from `GlobalProxy`, `DomainStrategy`
  kept. Entries the bundled geo files or Xray-core cannot serve (other
  geosite/geoip categories, `ext:`, invalid IPs/regexps) are skipped and counted,
  and the profile is checked with Xray-core (`testXray`) before it is stored, so
  the tunnel always starts. Imported profiles appear in the routing sheet
  (swipe to delete). Note: iOS gives the `happ://` scheme to only one installed app.
* **On-demand** is always off.

Supported links: `vless://`, `vmess://` (AEAD and legacy v2rayN JSON),
`trojan://`, `ss://`, `socks://`, `hysteria2://` / `hy2://`, `wireguard://`,
Base64 subscriptions and Xray JSON (single config or array). TUIC is not
supported by Xray-core.

Subscription metadata: `subscription-userinfo`, `profile-title`,
`profile-update-interval`, `support-url`, `profile-web-page-url`, `announce`
(headers or `#key: value` lines in the body, `base64:` values allowed).

## Building

Everything is built by GitHub Actions ([ios-build.yml](../.github/workflows/ios-build.yml))
on a macOS runner; no Mac is needed to change the app.

* Push to `main` / `ios-app` (paths `ios/**`) → artifact **`RockBlack-unsigned.ipa`**
  (or **`RockBlack.ipa`** when signing secrets are set) with `SHA256SUMS`.
* The `screenshots` job runs the unit tests on a simulator and uploads
  **`ios-screenshots`** (main screen in en/ru/de, dark/light, demo data via
  the `-demo` launch argument). It never blocks the build.
* **Actions → iOS build → Run workflow** with *release* checked (from `main`)
  publishes `ios-vX.Y.Z` titled `iOS vX.Y.Z` with the IPA and `SHA256SUMS`,
  then updates `RELEASE.json` (`ios` entry) and the `latest` tag.

Locally on a Mac (Xcode 16+):

```sh
cd ios
bash scripts/fetch-libxray.sh
bash scripts/fetch-geodata.sh
brew install xcodegen && xcodegen generate
open RockBlack.xcodeproj
```

Set your team in *Signing & Capabilities* for both targets; the
Network Extension capability (Packet Tunnel) and the app group
`group.tech.rockblack.app` must be enabled for both App IDs.

## Signing secrets

Settings → Secrets and variables → Actions:

| Secret | Value |
|:--|:--|
| `IOS_CERT_P12_BASE64` | base64 of the Apple Distribution (or Development) certificate `.p12` |
| `IOS_CERT_PASSWORD` | password of the `.p12` |
| `IOS_PROVISION_APP_BASE64` | base64 of the provisioning profile for `tech.rockblack.app` |
| `IOS_PROVISION_TUNNEL_BASE64` | base64 of the provisioning profile for `tech.rockblack.app.tunnel` |
| `IOS_TEAM_ID` | Apple Developer team ID |
| `IOS_EXPORT_METHOD` *(optional)* | `ad-hoc`, `app-store-connect`, `development` or `enterprise`; default: derived from the app profile |
| `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`, `APP_STORE_CONNECT_PRIVATE_KEY` *(optional)* | App Store Connect API key (`.p8` contents); with an App Store profile the IPA is uploaded to TestFlight |

Both App IDs need the **Network Extensions** capability and the **App Groups**
capability with `group.tech.rockblack.app`; the profiles must include them.
`base64 -i profile.mobileprovision | pbcopy` produces the secret values.

## Installing

* **Signed IPA** (secrets set): ad-hoc builds install on the devices listed in
  the profile (Apple Configurator, Finder, or an OTA manifest); App Store
  builds go to TestFlight / App Store review.
* **`RockBlack-unsigned.ipa`**: the binaries carry the entitlements with an
  ad-hoc signature.
  * **TrollStore** installs it directly (entitlements are preserved).
  * **AltStore / SideStore / Sideloadly / esign / `codesign`**: re-sign with
    your own Apple ID. Packet tunnel extensions require the Network
    Extension entitlement, which Apple grants **only to paid Apple Developer
    Program accounts** — with a free Apple ID the app installs but cannot
    start the VPN.
* A normal install from the App Store / TestFlight always requires a paid
  Apple Developer account (Network Extension + App Groups).

The VPN cannot run in the iOS simulator (NetworkExtension is device-only);
the simulator is used for UI tests and screenshots.
